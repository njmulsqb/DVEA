Guide: What is happening?

This window's configuration badges above are read live from this actual window — not hardcoded — so what they say is what's genuinely enforced here.

The injection point below renders whatever you submit straight into the page via innerHTML, unsanitized. Your script will execute. But this window is hardened: sandbox on, context isolation on, no Node integration, and no preload exposes any privileged API to this page. XSS here can attack the page — read what's on screen, read renderer storage, phish a user inside the page itself — but it cannot touch Node.js, the filesystem, or the operating system. Prove what contained XSS can still do, then watch it hit the wall.

Objective: Using only the injection point below, complete the four tasks in order of increasing ambition — steal on-page data, read renderer storage, harvest a phished credential, then try to break out of the renderer entirely. No payloads are given here; craft your own and watch the attacker view and task list respond.

Sensitive data on this page

    Tasks

    • Unsolved Task 1 — Steal page data. Use XSS to read the session token displayed above out of the DOM and get it into the attacker view.

    • Unsolved Task 2 — Read renderer storage. This window's localStorage holds a secret under dvea_secret. Use XSS to read it and surface it in the attacker view — the value you recover is itself the flag.

    • Unsolved Task 3 — In-page phishing. Use XSS to inject a fake login form into the page and capture a submitted credential into the attacker view.

    • Unsolved Task 4 — Try to escape. Attempt to break out of the renderer — reach Node.js, the filesystem, or the OS. Because this window is genuinely hardened, watch it fail.
