Route: Untrusted Navigation

This route demonstrates how an attacker-crafted dvea:// deep link can make the app open a native-looking window and load attacker content with no visible address-bar signal.

Objective: Craft a deep link that loads attacker-controlled content in the trusted app window.

How to try it: A real deep link has the shape dvea://navigate?url=<url> — whatever URL you supply is opened in a new, native-looking app window with no checks. Point it at any external content the app shouldn't trust, or at DVEA's own bundled fake-login.html page to see the credential-harvesting impact in the attacker view below.

Try It

On an installed (packaged) build, the OS registers the dvea:// scheme for DVEA — opening a link like dvea://navigate?url=https://example.com from anywhere (a browser address bar, an email, a terminal) pops open a new, native-looking DVEA window loading that URL, with no address bar and no confirmation.

If your browser searches for the text instead of opening DVEA, the scheme isn't registered with the OS — check with xdg-mime query default x-scheme-handler/dvea, which should print dvea.desktop. Browsers only hand a custom scheme to the OS when a handler for it exists.

Running from source doesn't reliably register the scheme with the OS, so a real dvea:// link won't dispatch to the app during development — use the simulator below instead.
