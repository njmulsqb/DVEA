Guide: What is happening?

You configured the hard part right — sandbox, isolation, no Node integration. But this window's preload exposes one privileged function to the page, and XSS climbs straight through it to the OS. Correct core config, one over-eager bridge, full compromise.

The injection point below is the exact same sink as Challenge 1: whatever you submit is rendered straight into the page via innerHTML, unsanitized. The difference isn't the injection — it's what this window's preload put within reach of it.

Objective: Using only the injection point below, discover what this window's preload exposed on window, call it successfully, then use it to reach the operating system and retrieve proof. No payloads are given here; craft your own and watch the attacker view and task list respond.
