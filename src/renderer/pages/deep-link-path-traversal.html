Deep Link → Path Traversal

Deep link reads an arbitrary file path supplied by the attacker.

Route: Arbitrary File Read

Some apps accept deep links that open files. If the main process reads the supplied path with no validation, an attacker can craft a deep link that reads sensitive host files.

Objective: Craft a deep link that reads a file outside the app's intended directory.

How to try it: A real deep link has the shape dvea://open?path=<file path> — whatever path you supply is read straight from disk with no checks. Try a system file that has nothing to do with DVEA (e.g. /etc/passwd) to prove the read isn't confined to the app at all — DVEA also bundles a small marker file alongside its own pages if you want a reliable target to confirm the read works before going further.

Try It

On an installed (packaged) build, the OS registers the dvea:// scheme for DVEA — opening a link like dvea://open?path=/etc/passwd from anywhere (a browser address bar, an email, a terminal) drives this window to read and display that file's contents.

Running from source doesn't reliably register the scheme with the OS, so a real dvea:// link won't dispatch to the app during development — use the simulator below instead.
