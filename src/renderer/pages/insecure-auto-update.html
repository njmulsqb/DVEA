Insecure Auto-Update — cf. CVE-2024-39698

Simulated updater demonstrating insecure update feeds and missing signature verification.

✗ Feed transport: HTTP allowed ✗ Signature/integrity: optional

Guide: What is happening?

This demo runs a bundled update-feed server locally and a vulnerable auto-updater in the main process. In VULNERABLE mode the updater will fetch a manifest over HTTP with no signature or integrity checks and then download and execute whatever payload the manifest specifies. The attacker can serve a poisoned manifest and payload (no user interaction required).

In HARDENED mode the updater requires HTTPS and verifies a trusted HMAC signature and payload hash; the poisoned manifest is rejected and nothing runs.

Attack Scenario

Real threat: an app that checks an HTTP update feed with no signature verification can be MITM'd (public Wi‑Fi, DNS poisoning, compromised CDN). An attacker returns a manifest pointing at their payload; the app downloads and runs it as a trusted update, enabling silent RCE across users. The sentinel is a stand-in for arbitrary attacker code (reverse shell, credential exfiltration).

Grounding: related issues include CVE-2024-39698 (electron-updater Windows signature bypass) and Doyensec's publisherName string-comparison bypass. This module demonstrates the general pattern; it does not reproduce that Windows-specific bug but is grounded in those real-world examples.
