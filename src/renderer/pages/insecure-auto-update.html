Insecure Auto-Update — cf. CVE-2024-39698

An updater that trusts its feed executes attacker code in the main process — supply-chain RCE

✗ Feed transport: plaintext HTTP allowed ✗ Integrity: signature/hash unverified in VULNERABLE mode ✓ HARDENED mode: HTTPS + hash + signature enforced

Guide: What is happening?

A web page's "update" is just the server sending new HTML/JS that runs inside the browser sandbox — worst case, a compromised web app. An Electron app's auto-updater is categorically different: it fetches code that runs in the main process, with full Node.js and OS privileges, outside any sandbox. So the question "is this update authentic?" is the only thing standing between the network and code execution on every user's machine.

This module runs a bundled update-feed server locally (standing in for an attacker's MITM feed) and a real, vulnerable updater in the main process. In VULNERABLE mode the updater fetches a manifest over plaintext HTTP with no transport security and no integrity check, then downloads and eval()s whatever payload the manifest names. No user interaction is required. In HARDENED mode the same updater requires HTTPS and verifies a payload hash and a trusted HMAC signature before running anything.

The danger isn't "run one payload" — it's the reach. A single poisoned feed (public Wi-Fi MITM, DNS poisoning, a compromised CDN or update server) turns into remote code execution across the entire user base, silently, with persistence and data theft available to the payload because it runs with the app's own privileges.

Objective: This app ships an updater that behaves as if anything its feed returns is trustworthy. Prove that's fatal: get it to (1) accept an update over plaintext HTTP, and (2) execute an unsigned/forged payload so attacker code runs in the main process. Then (3) switch on the hardening and confirm the same forged update is now rejected. Work out which feed and mode to use yourself — nothing here hands you the exploit.
This genuinely runs code. Starting the server opens real local HTTP/HTTPS listeners, and a successful VULNERABLE update eval()s a payload in the main process that writes marker files under /tmp (and reads a planted decoy wallet). The payloads are DVEA-controlled and safe to run repeatedly; Reset stops the server and clears the markers.

Recon: the update feed

Start the local feed server, then point the updater at one of its endpoints. The server serves a manifest for two channels over both transports — the endpoint URLs appear here once it's running. It also plants a decoy secret on the host that a payload with real main-process access could read.
