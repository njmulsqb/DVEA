The flagship challenge. No walkthrough on this page — figure out the chain yourself.

Objective

Below is a form that stores a display name and opens it in an in-app analytics window. Somewhere past that window sits a session token you should not be able to reach.

Get the token out. Submit it below to claim the flag.

Scope

  • Everything you need is reachable from this page and the analytics window it opens — no other module's flags or handlers are part of this chain.
  • The analytics window enforces a Content-Security-Policy. Treat it as real; it is not a red herring.
  • DevTools are fair game. So is reading anything the packaged app ships.
  • You are not looking for a scripting bug. You are looking for something CSP does not cover.

Shape of this one: an injection that survives a security control by not being the kind of thing that control was built to stop, followed by a trust boundary that was drawn around the wrong thing.

Stuck? Hints

Reveal one at a time. Each names a concept, not a payload.

Hint 1

A Content-Security-Policy restricts what can execute. It says nothing about what can be parsed. Not every way to make a page go somewhere else involves running a script.

Hint 2

Once the analytics window leaves the page it started on, ask yourself what actually stays behind. A window's privileged capabilities are attached to something — is it the page currently loaded, or the window itself?

Hint 3

You now have a privileged window showing content you don't control. Whatever that window's preload exposes to the page is exposed to any page it happens to be showing. Go find out what it exposes, and whom it checks before answering.
